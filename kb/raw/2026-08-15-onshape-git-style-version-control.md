## Core premise

Onshape positions Git-style version control as a fundamental shift in mechanical design
workflow, arguing that "Innovation doesn't occur by accident - it's the direct result of
rapid iteration," and contrasting cloud-native CAD with file-based systems largely
unchanged since drive-letter file management.

## Claimed features

- **Instant branching** — users can "create a branch - an isolated workspace for
  experimentation," eliminating file duplication and fear of modifying primary designs.
- **Precision merging** — the platform "clearly visualizes differences between branches,
  just like GitHub does for software code." Users select which modifications to retain.
- **Workspace protection** — organizations can restrict modification of protected
  workspaces through a "controlled review and merge process."

## Problems attributed to file-based CAD

- **Cost of change:** late modifications require "tedious file duplications, manual
  conflict resolution, and hours spent fixing broken references."
- **Cost of delay:** single-user restrictions mean "only one person can work on a design at
  a time."

## Collaboration model

Simultaneous team editing comparable to Google Docs — "multiple users can edit
simultaneously, iterate freely, and see each other's changes in real time."

## Not stated in the source

The extract contains no discussion of whether branch/merge history is exportable, or of
what happens to that history outside the Onshape platform.
